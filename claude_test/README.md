## Key Findings

- **MoveJ** returns error 101 or 154 on firmware V3.9.1; use **ServoJ** instead.
- Init sequence: `RobotEnable(0)` -> `ResetAllError` -> `RobotEnable(1)` -> `Mode(0)` -> `ServoMoveStart`.
- ServoJ XMLRPC call takes **7 params** (no `id` arg); the SDK wrapper passes 8.
- `main_code=1` indicates a residual error state; must disable-then-enable to clear.
- **Init settle times must be ≥1 s** per step; 0.2–0.3 s causes persistent ServoJ error 101.
- **ServoJ must run from the main thread**; daemon threads always get error 101 on this firmware.
- Hold-position ServoJ (same position) returns 101; after ~40 consecutive 101s the controller terminates the session (error 14).

| `debug_pi0_meta_load.py` | Issue #123: proves the meta-device Pi0 load is weight-identical to the old eager load. Loads one checkpoint twice -- the pre-fix way (full float32 random init of 4.03 B parameters on CPU, `.to(cuda)`, then `load_state_dict` from a host-memory state dict) and the post-fix way (`PI0Policy.from_pretrained`, meta skeleton + `assign=True`) -- then compares every parameter **and buffer** for dtype, device, and bit-exact values, and prints the wall-clock cost of each path. The buffer comparison is the point: the six non-persistent buffers (`position_ids`, `embed_scale`, rotary `inv_freq`/`original_inv_freq`) are absent from the checkpoint and are the only place the new path can drift. Run it twice: once on a Hub checkpoint (already saved in the bfloat16/float32 mix, 103.2 s -> 2.0 s, 51x) and once on `models/pi0_base_v051compat` with `--dtype bfloat16` (777 pure-float32 tensors, 117.4 s -> 9.3 s, 13x). The second run is the one that matters for training: `assign=True` alone would have given every fine-tune a float32 model, ignoring `--policy.dtype`, until `apply_precision_layout` was added. Both report PASS on all 784 tensors. Needs ~20 GB of VRAM for the two models. `--smoke` additionally pushes one synthetic observation through the real `make_pre_post_processors` + `predict_action_chunk` path (a (1, 50, 7) chunk in 0.56 s, all finite), which the tensor comparison alone would not catch; `--skip-old` skips the slow pre-fix load, and `--bench N` A/B-times N action chunks on both models in one process (105.3 ms vs 105.7 ms median -- the load path does not affect inference speed). `--policy pi05` runs the same checks against `PI05Policy`. Usage: `CUDA_VISIBLE_DEVICES=2 python claude_test/debug_pi0_meta_load.py [--repo REPO] [--policy pi0|pi05] [--dtype bfloat16] [--smoke] [--skip-old] [--bench 20]`. |
